Политика конфиденциальности

Последнее обновление: 27 сентября 2026 года

OTPulse — офлайн-аутентификатор. Приложение хранит данные аккаунтов аутентификатора на устройстве и защищает секретные ключи TOTP с помощью безопасного хранилища Android. OTPulse не предоставляет систему аккаунтов, не содержит рекламы и не отправляет секретные ключи или сгенерированные одноразовые коды на серверы OTPulse.

Какие данные обрабатывает приложение

Названия сервисов и аккаунтов, параметры TOTP, секретные ключи и сгенерированные коды обрабатываются локально на устройстве. Секретные ключи защищаются средствами Android Keystore. Приватные данные приложения исключены из облачного резервного копирования и переноса между устройствами средствами Android.

Сканирование QR-кодов

На Android OTPulse использует Google Code Scanner, предоставляемый сервисами Google Play. Обработка изображения выполняется на устройстве, а OTPulse получает результат сканирования. OTPulse не сохраняет кадры камеры.

Согласно документации Google для ML Kit, используемый SDK может собирать ограниченные сведения об устройстве и приложении, идентификаторы установки, показатели производительности, конфигурацию API, сведения о событиях функций и коды ошибок для диагностики и аналитики использования. Google указывает, что эти данные шифруются при передаче и не передаются третьим лицам. Автоматическое масштабирование сканера в OTPulse отключено.

Подробнее: требования Google к раскрытию данных ML Kit.

Bluetooth

На поддерживаемых устройствах Android OTPulse может работать как Bluetooth HID-клавиатура. Одноразовый код отправляется только после того, как пользователь выбрал сопряжённый компьютер и явно запустил отправку. Для этого Android запрашивает разрешение «Устройства поблизости». Идентификаторы Bluetooth-устройств не отправляются на серверы OTPulse.

Резервные копии и буфер обмена

Экспорт и импорт резервной копии выполняется только по инициативе пользователя через системный интерфейс выбора документов. Экспортированный файл содержит секретные ключи в открытом виде; пользователь отвечает за его безопасное хранение.

При копировании одноразового кода он помещается в системный буфер обмена. Другие приложения или системные службы могут получать доступ к буферу обмена в соответствии с правилами Android.

Хранение и удаление

Данные аутентификатора остаются на устройстве, пока пользователь не удалит отдельный аккаунт, не очистит данные приложения или не удалит OTPulse. У OTPulse нет серверного аккаунта или серверного хранилища пользовательских данных, поэтому отдельный запрос разработчику на удаление данных не требуется.

Изменения политики

Эта политика может обновляться при изменении функций приложения, используемых SDK или требований законодательства. Актуальная версия всегда публикуется на этой странице с датой последнего обновления.

Privacy Policy

Last updated: September 27, 2026

OTPulse is an offline-first authenticator. The app stores authenticator account data on the device and protects TOTP secret keys using Android secure storage. OTPulse does not provide an account system, contains no advertising, and does not send secret keys or generated one-time codes to OTPulse servers.

Data processed by the app

Service and account labels, TOTP parameters, secret keys, and generated codes are processed locally on the device. Secret keys are protected using Android Keystore. The app's private data is excluded from Android cloud backup and device-to-device transfer.

QR code scanning

On Android, OTPulse uses Google Code Scanner, provided by Google Play services. Image processing occurs on the device, and OTPulse receives the scan result. OTPulse does not retain camera frames.

According to Google's ML Kit documentation, the SDK may collect limited device and application information, per-installation identifiers, performance metrics, API configuration, feature event information, and error codes for diagnostics and usage analytics. Google states that this data is encrypted in transit and is not shared with third parties. Scanner auto-zoom is disabled in OTPulse.

Learn more in Google's ML Kit data disclosure guidance.

Bluetooth

On supported Android devices, OTPulse can act as a Bluetooth HID keyboard. A one-time code is sent only after the user selects a paired computer and explicitly starts sending. Android requests the Nearby devices permission for this feature. Bluetooth device identifiers are not transmitted to OTPulse servers.

Backups and clipboard

Backup export and import are initiated by the user through the system document picker. Exported files contain authenticator secret keys in plain text, and the user is responsible for storing them securely.

When a one-time code is copied, it is placed in the system clipboard. Other apps or system services may access clipboard contents according to Android rules.

Retention and deletion

Authenticator data remains on the device until the user deletes an individual account, clears the app's data, or uninstalls OTPulse. OTPulse has no server-side account or user-data storage, so no separate deletion request to the developer is necessary.

Changes to this policy

This policy may be updated when app functionality, included SDKs, or legal requirements change. The current version is always published on this page with its last-updated date.
